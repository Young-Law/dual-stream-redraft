# DSA v2.10.1 review corrections

This revision repairs false-success paths and clarifies the research contract. It does not establish improved deception detection, production device attestation, or operational independence of a local validator. The accompanying proposal remains a specification with evaluation targets, not an experimental report.

## Evidence representation

Mandatory compact scores are **full-vocabulary softmax probabilities at temperature 1 before decoder controls**, retained as top-K without renormalizing the retained subset. They are not recoverable raw logits. The uint8 representation stores `round(255 * p)` (nearest integer, ties to even) and decodes as `q / 255`. The step is 1/255 and absolute error per candidate is at most 1/510. Small probabilities may become zero and distinct scores may tie; original candidate order matters. Relative error is unbounded near zero. Missing tail values and exact full-distribution entropy cannot be reconstructed. Nonfinite or out-of-range probability inputs must be rejected.

## Acyclic artifact and retention binding

1. Fix an optional policy commitment that contains no reference to the finalized artifact. A JSON policy uses UTF-8, sorted keys, compact separators, ASCII escaping, and finite JSON; a supplied string commits its exact UTF-8 bytes.
2. Store that policy hash, or zero, in the manifest's legacy-named `retention_requirement_hash` field. This is **not** the hash of the final signed requirement.
3. Encode the entire final artifact. Compute SHA-256 with only the manifest's 32-byte `artifact_content_hash` field replaced by zero; include all remaining bytes. Store the digest without changing other bytes.
4. Issue a **detached** signed RetentionRequirement binding the completed artifact hash, policy commitment, schema, counts, retention bounds, and horizon. Manifest signatures are also detached.
5. Validate the persisted object before issuing a detached receipt. The receipt binds the final signed requirement envelope, not merely the embedded policy commitment. Each signed schema defines its canonical signing bytes independently.

This preserves the V3.3 wire layout and removes the self-reference. A requirement hash must never be written back into a finalized artifact.

## Verification and storage meaning

A structural check is not a completed keyed-policy check. An artifact declaring keyed sampling requires authorized replay material; absent keys and failed replay cannot return a policy PASS. Failed or incomplete local verification cannot report LOCAL_PASS.

A work certificate reports actual work, including partial work on failure. Reading, decoding, or constructing full artifact collections counts as materialization. Sparse-span processing must account for actual interval work, rather than reporting only the number of spans. Portable operation counts are distinct from allocator bytes, allocation counts, RSS, and timing, which depend on runtime and platform. Unmeasured calibration or allocation values must be unavailable rather than fabricated zeros or relabeled raw elapsed time.

Retention completion requires full schema decoding, counts, integrity, and policy bounds checked against the stored object. A byte floor and content hash alone do not establish reconstructability. Possession responses must provide retrieved bytes and authenticated proofs bound to an immutable object version, unpredictable nonce, selected indices, and deadline. Any configured signature must be verified. Copying an expected hash from a challenge is not proof of possession. Challenges must read storage rather than the producer's original buffer. Same-process issuer and validator keys are useful for tests but cannot establish independent production validation.

## Sampling and evaluation

Under ideal independent sampling, an event with `m` eligible tokens has widening coverage `1 - (1 - p)^m`. At `p = 0.005` this is 0.5% for one token, 4.9% for ten, and 39.4% for 100. This describes pseudorandom coverage across secret keys or contexts; a fixed key and context replay deterministically. Coverage is not detection: the widened candidates must contain a useful signal and the audit must recognize it.

Preregister event definitions, sample rates, byte ceilings, false-positive and review budgets, and minimum useful gains over output-only and rank-only baselines. Evaluate held-out event recall, confidence intervals, coverage, and detection conditional on widening. Run architecture and runner-variance experiments separately. Unit and conformance fixtures establish implementation properties, not model-detection efficacy.

## Combined PR 35 and 36 integration

The security-hardened streaming parser now emits canonical version-2 certificates
through `dualstream.work_certificate`; the earlier duplicate verifier certificate
has been removed. Version-1 signing bytes remain compatible. Version 2 binds
completion state and parser limits, uses a distinct streaming profile, and
separates runtime diagnostics from signed work. Logical read-buffer events and
wire residency are explicitly distinguished from unmeasured allocator calls and
measured tracemalloc peaks. Failed local checks cannot certify completion.

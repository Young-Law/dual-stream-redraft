# DSA v2.10 Phase 1 implementation notes

The repository implements the compact binary V3.3 evidence wire foundation, integrated model-generation path, legacy decoding compatibility, canonical artifact hashing, and authorized keyed-selection replay. Portable verifier governance, signed tension-map governance, and complete end-to-end retention assurance remain under implementation.

## Binary layout summary

All V3.3 integers are little-endian. Artifacts begin with the existing compact-family magic `DSAEV29\0` followed by a 16-bit version field set to `0x0303`. The V3.3 body contains a fixed-width sequence header, a SHA-256 digest and bounded JSON metadata block for non-token public replay context, ordered chunk records with compact token payloads, sparse span records, and a fixed-width manifest. Token records encode only compact binary values: effective-K delta, chosen-rank or fallback chosen-id marker, trigger flags, record flags, and repeated `(uint32 token_id, uint8 quantized_score)` candidate entries.

## Canonical artifact hash

The manifest stores `artifact_content_hash`. Encoder and decoder compute it over the complete final artifact preimage with only the manifest's `artifact_content_hash` bytes set to zero. The decoder independently recomputes this preimage and rejects a mismatch rather than overwriting the serialized hash.

## Scope boundary

This phase does not implement the full portable verifier work-certificate system, signed historical-tension YAML governance, or full retention requirement/receipt lifecycle. DSA-P assurance remains outside the software-only Phase 1 boundary.
